# Kubernetes로 설정하기

이 문서는 Kubernetes 환경에서 SeaTunnel을 빠르게 사용하는 방법을 안내합니다.

## 선행 조건

로컬 환경에 다음 도구가 설치되어 있다고 가정합니다.

- [docker](https://docs.docker.com/)
- [kubernetes](https://kubernetes.io/)
- [helm](https://helm.sh/docs/intro/quickstart/)

따라서 로컬에서 `kubectl`, `helm` 명령을 바로 사용할 수 있어야 합니다.

예시로 Kubernetes [minikube](https://minikube.sigs.k8s.io/docs/start/)를 사용하면 아래 명령으로 클러스터를 시작할 수 있습니다.

```bash
minikube start --kubernetes-version=v1.23.3
```

```Dockerfile
FROM flink:1.13

ENV SEATUNNEL_VERSION="2.3.13"
ENV SEATUNNEL_HOME="/opt/seatunnel"

RUN wget https://dlcdn.apache.org/seatunnel/${SEATUNNEL_VERSION}/apache-seatunnel-${SEATUNNEL_VERSION}-bin.tar.gz
RUN tar -xzvf apache-seatunnel-${SEATUNNEL_VERSION}-bin.tar.gz

```

그다음 아래 명령으로 이미지를 빌드합니다.
```bash
docker build -t seatunnel:2.3.13-flink-1.13 -f Dockerfile .
```
`seatunnel:2.3.13-flink-1.13` 이미지는 배포를 진행하려면 호스트(minikube)에 존재해야 합니다.

다음 명령으로 minikube에 이미지를 로드합니다.
```bash
minikube image load seatunnel:2.3.13-flink-1.13
```

--set image.repository=apache/flink-kubernetes-operator

## SeaTunnel 애플리케이션 실행

**실행 준비:** SeaTunnel은 이미 [기본 구성](https://github.com/apache/seatunnel/tree/dev/config)을 제공합니다.

<TabItem value="flink">

이 가이드에서는 [seatunnel.streaming.conf](https://github.com/apache/seatunnel/blob/2.3.13-release/config/v2.streaming.conf.template)를 사용합니다.

```conf
env {
  parallelism = 1
  job.mode = "STREAMING"
  checkpoint.interval = 2000
}

source {
    FakeSource {
      plugin_output = "fake"
      row.num = 160000
      schema = {
        fields {
          name = "string"
          age = "int"
        }
      }
    }
}

transform {
  FieldMapper {
    plugin_input = "fake"
    plugin_output = "fake1"
    field_mapper = {
      age = age
      name = new_name
    }
  }
}

sink {
  Console {
    plugin_input = "fake1"
  }
}
```

seatunnel.streaming.conf를 Pod에 마운트할 수 있도록 Kubernetes에서 `seatunnel-config`라는 ConfigMap을 생성합니다.
```bash
kubectl create cm seatunnel-config \
--from-file=seatunnel.streaming.conf=seatunnel.streaming.conf
```

앞선 단계대로 Flink Kubernetes Operator가 실행 중이라면 이제 Flink(SeaTunnel) 작업을 제출할 준비가 된 것입니다.
- `seatunnel-flink.yaml` FlinkDeployment 매니페스트를 생성합니다.
```yaml
apiVersion: flink.apache.org/v1beta1
kind: FlinkDeployment
metadata:
  name: seatunnel-flink-streaming-example
spec:
  image: seatunnel:2.3.13-flink-1.13
  flinkVersion: v1_13
  flinkConfiguration:
    taskmanager.numberOfTaskSlots: "2"
  serviceAccount: flink
  jobManager:
    replicas: 1
    resource:
      memory: "1024m"
      cpu: 1
  taskManager:
    resource:
      memory: "1024m"
      cpu: 1
  podTemplate:
    spec:
      containers:
        - name: flink-main-container
          volumeMounts:
            - name: seatunnel-config
              mountPath: /data/seatunnel.streaming.conf
              subPath: seatunnel.streaming.conf
      volumes:
        - name: seatunnel-config
          configMap:
            name: seatunnel-config
            items:
            - key: seatunnel.streaming.conf
              path: seatunnel.streaming.conf
  job:
    jarURI: local:///opt/seatunnel/starter/seatunnel-flink-13-starter.jar
    entryClass: org.apache.seatunnel.core.starter.flink.SeaTunnelFlink
    args: ["--config", "/data/seatunnel.streaming.conf"]
    parallelism: 2
    upgradeMode: stateless
```

- 예제 애플리케이션을 실행합니다.
```bash
kubectl apply -f seatunnel-flink.yaml
```

다음 명령으로 SeaTunnel 클러스터에서 사용하는 일부 설정 파일을 ConfigMap에 로드합니다.

다음과 같이 로컬에 YAML 파일을 생성합니다.

- `hazelcast-client.yaml`을 생성합니다.

```yaml

hazelcast-client:
  cluster-name: seatunnel
  properties:
    hazelcast.logging.type: log4j2
  network:
    cluster-members:
      - localhost:5801

```
- `hazelcast.yaml`을 생성합니다.

```yaml

hazelcast:
  cluster-name: seatunnel
  network:
    rest-api:
      enabled: true
      endpoint-groups:
        CLUSTER_WRITE:
          enabled: true
        DATA:
          enabled: true
    join:
      tcp-ip:
        enabled: true
        member-list:
          - localhost
    port:
      auto-increment: false
      port: 5801
  properties:
    hazelcast.invocation.max.retry.count: 20
    hazelcast.tcp.join.port.try.count: 30
    hazelcast.logging.type: log4j2
    hazelcast.operation.generic.thread.count: 50

```
- `seatunnel.yaml`을 생성합니다.

```yaml
seatunnel:
  engine:
    history-job-expire-minutes: 1440
    backup-count: 1
    queue-type: blockingqueue
    print-execution-info-interval: 60
    print-job-metrics-info-interval: 60
    slot-service:
      dynamic-slot: true
    checkpoint:
      interval: 10000
      timeout: 60000
      storage:
        type: hdfs
        max-retained: 3
        plugin-config:
          namespace: /tmp/seatunnel/checkpoint_snapshot
          storage.type: hdfs
          fs.defaultFS: file:///tmp/ # 디렉터리에 쓰기 권한이 있는지 확인하세요
```

다음 명령으로 설정 파일을 위한 ConfigMap을 생성합니다.

```bash
kubectl create configmap hazelcast-client  --from-file=hazelcast-client.yaml
kubectl create configmap hazelcast  --from-file=hazelcast.yaml
kubectl create configmap seatunnelmap  --from-file=seatunnel.yaml

```

핫 배포를 위해 Reloader를 배포합니다.
여기서는 설정 파일 등 변경이 발생하면 자동으로 Pod를 재시작하도록 Reloader를 사용합니다. 필요 없다면 설정 값을 직접 지정하고 Reloader를 사용하지 않아도 됩니다.

- [Reloader](https://github.com/stakater/Reloader/)

```bash
wget https://raw.githubusercontent.com/stakater/Reloader/master/deployments/kubernetes/reloader.yaml
kubectl apply -f reloader.yaml

```

- `seatunnel-cluster.yml`을 생성합니다.
```yaml
apiVersion: v1
kind: Service
metadata:
  name: seatunnel
spec:
  selector:
    app: seatunnel
  ports:
  - port: 5801
    name: seatunnel
  clusterIP: None
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: seatunnel
  annotations:
    configmap.reloader.stakater.com/reload: "hazelcast,hazelcast-client,seatunnelmap"
spec:
  serviceName: "seatunnel"
  replicas: 3  # 환경에 맞게 replicas 값을 조정하세요
  selector:
    matchLabels:
      app: seatunnel
  template:
    metadata:
      labels:
        app: seatunnel
    spec:
      containers:
        - name: seatunnel
          image: seatunnel:2.3.13
          imagePullPolicy: IfNotPresent
          ports:
            - containerPort: 5801
              name: client
          command: ["/bin/sh","-c","/opt/seatunnel/bin/seatunnel-cluster.sh -DJvmOption=-Xms2G -Xmx2G"]
          resources:
            limits:
              cpu: "1"
              memory: 4G
            requests:
              cpu: "1"
              memory: 2G
          volumeMounts:
            - mountPath: "/opt/seatunnel/config/hazelcast.yaml"
              name: hazelcast
              subPath: hazelcast.yaml
            - mountPath: "/opt/seatunnel/config/hazelcast-client.yaml"
              name: hazelcast-client
              subPath: hazelcast-client.yaml
            - mountPath: "/opt/seatunnel/config/seatunnel.yaml"
              name: seatunnelmap
              subPath: seatunnel.yaml
            - mountPath: /data/seatunnel.streaming.conf
              name: seatunnel-config
              subPath: seatunnel.streaming.conf
      volumes:
        - name: hazelcast
          configMap:
            name: hazelcast
        - name: hazelcast-client
          configMap:
            name: hazelcast-client
        - name: seatunnelmap
          configMap:
            name: seatunnelmap
        - name: seatunnel-config
          configMap:
            name: seatunnel-config
            items:
            - key: seatunnel.streaming.conf
              path: seatunnel.streaming.conf
```

- 클러스터 시작:
```bash
kubectl apply -f seatunnel-cluster.yml
```
이후 다음 명령으로 Pod 내부의 SeaTunnel 설정을 수정합니다.

```bash
kubectl edit cm hazelcast
```
`member-list` 항목을 클러스터 주소로 변경합니다.

이는 Headless Service를 통한 접근 방식입니다.

일반적으로 Pod 간 접근 형식은 `[pod-name].[service-name].[namespace].svc.cluster.local`입니다.

예시:
```bash
- seatunnel-0.seatunnel.default.svc.cluster.local
- seatunnel-1.seatunnel.default.svc.cluster.local
- seatunnel-2.seatunnel.default.svc.cluster.local
```
```bash
kubectl edit cm hazelcast-client
```
`cluster-members` 항목을 클러스터 주소로 변경합니다.

예시:
```bash
- seatunnel-0.seatunnel.default.svc.cluster.local:5801
- seatunnel-1.seatunnel.default.svc.cluster.local:5801
- seatunnel-2.seatunnel.default.svc.cluster.local:5801
```
잠시 후 Pod가 자동으로 재시작되며 SeaTunnel 설정이 갱신됩니다.

```bash
kubectl edit cm hazelcast-client
```
After we wait for all pod updates to be completed, we can use the following command to check if the configuration inside the pod has been updated

```bash
kubectl exec -it  seatunnel-0  -- cat /opt/seatunnel/config/hazelcast-client.yaml
```
Afterwards, we can submit tasks to any pod

```bash
kubectl exec -it  seatunnel-0  -- /opt/seatunnel/bin/seatunnel.sh --config /data/seatunnel.streaming.conf
```
