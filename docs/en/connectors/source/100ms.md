# 100ms

The `OneHundredMs` source reads the 100ms server-side API as a bounded crawl. Its parallelism is one. The end-to-end suite targets SeaTunnel Zeta.

Authenticate with either `token` or the pair `access_key` and `secret_key`. With the key pair, the source signs a 24-hour management JWT and refreshes it before expiry. An HTTP 401 can trigger one regenerated token within the attempt limit. A supplied token is sent unchanged. Use the deployment's secret mechanism for these options. [100ms authentication](https://www.100ms.live/docs/get-started/v2/get-started/security-and-tokens)

## Source options

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `api_url` | String | `https://api.100ms.live` | Trusted HTTPS origin. Optional port and trailing slash are allowed. |
| `token` | String |  | Existing management token without the Bearer prefix. Supply only when using token authentication. |
| `access_key` | String |  | Application Access Key. Required with the application secret when generating a management token. |
| `secret_key` | String |  | Application secret used for HS256 signing. |
| `resources` | List&lt;String&gt; | All eight | Ordered subset of resource names. Each name can be selected once. |
| `start_date` | String |  | Inclusive ISO-8601 UTC lower bound for updates in rooms, templates and recordings, ending in Z. |
| `page_size` | Integer | `100` | List size from 10 to 100. |
| `max_pages` | Integer | `10000` | Maximum pages per list scan or child snapshot. Range 1–20,000. |
| `max_parents` | Integer | `10000` | Maximum unique parent IDs per selected child resource. Range 1–20,000. |
| `max_response_bytes` | Integer | `4194304` | Per-response byte limit applied separately to its wire and decompressed bodies. Range 1,024–16,777,216. |
| `max_records_per_response` | Integer | `5000` | Rows per response, including peer-map members. Range 1–20,000. |
| `connect_timeout_ms` | Integer | `10000` | TCP connection timeout in milliseconds. Range 1–300,000. |
| `read_timeout_ms` | Integer | `10000` | TLS handshake and response read inactivity timeout. Range 1–300,000 ms. |
| `request_timeout_ms` | Integer | `30000` | Total request time budget including I/O, parsing, retries, and waits. Range 1–300,000 ms. |
| `max_attempts` | Integer | `3` | Number of HTTP attempts per request including the first. Range 1–10. |

## Resources

| Resource | Rows |
| --- | --- |
| [`sessions`](https://www.100ms.live/docs/server-side/v2/api-reference/Sessions/list-sessions) | Active and inactive sessions. |
| [`rooms`](https://www.100ms.live/docs/server-side/v2/api-reference/Rooms/list-rooms) | Enabled and disabled rooms. Incremental field `updated_at`. |
| [`active_room_peers`](https://www.100ms.live/docs/server-side/v2/api-reference/active-rooms/list-peers) | One row per member of each room's peer map. A missing active room yields no peers. |
| [`templates`](https://www.100ms.live/docs/server-side/v2/api-reference/policy/list-templates) | Template objects. Incremental field `updatedAt`. |
| [`template_settings`](https://www.100ms.live/docs/server-side/v2/api-reference/policy/retrieve-settings) | One complete settings object per template. |
| [`templates_destinations`](https://www.100ms.live/docs/server-side/v2/api-reference/policy/retrieve-destinations) | One complete destinations object per template. |
| [`analytics_events`](https://www.100ms.live/docs/server-side/v2/api-reference/analytics/overview) | Per-room events. Each room's provider snapshot expires after 24 hours and the service exposes events for up to 30 days. |
| [`recordings`](https://www.100ms.live/docs/server-side/v2/api-reference/recordings/list-all-recordings) | Recording job metadata, with incremental field `updated_at`. |

The output columns are `resource`, `record_id`, nullable `parent_id`, nullable `updated_at`, and `data`. All have type STRING. `data` contains the complete JSON object, including nested values, nulls and exact decimal and integer values. Treat the payload as provider data. It can include user metadata or storage configuration.

The peer map key supplies `record_id` for peers. Settings and destinations use the parent template ID. Analytics uses the provider ID when present or a SHA-256 identifier for the JSON object when the response has no ID.

## Extraction and recovery

Without `start_date`, every selected resource is a full read. With it, the source applies the inclusive local update window from `start_date` through the first job start to rooms, templates, and recordings. Missing or unset update time falls back to creation time. If both are absent, a filtered read fails. The other resources remain full reads. Child discovery scans all rooms or templates regardless of the update window.

Cursors determine when lists finish. Responses with a valid next cursor continue even if the page is short or empty. Repeated cursors, repeated records across consecutive pages, unexpected response shapes, and exhausted bounds fail the crawl. Analytics continuation stays within its snapshot lifetime and a rejected or expired cursor fails without starting a replacement snapshot.

After a checkpoint, the reader resumes its next request and any saved child traversal. It retains the original upper timestamp. Keep the API origin, account, resources, page size and start date consistent when restoring. The provider lists can change while a job is running. The source does not provide a single remote snapshot across resources. Duplicates may occur if objects move between active/inactive or enabled/disabled scans, or if rows after the last checkpoint are replayed.

HTTPS uses the worker JVM trust store and verifies the hostname. The connector accepts gzip, bounds requests, and withholds error bodies from diagnostics. HTTP 429 and eligible 5xx responses retry with bounded backoff and respect a valid `Retry-After`. Redirects fail.

## Example

```hocon
env {
  job.mode = "BATCH"
  parallelism = 1
}

source {
  OneHundredMs {
    access_key = ${HMS_ACCESS_KEY}
    secret_key = ${HMS_SECRET_KEY}
    resources = ["rooms", "active_room_peers", "recordings"]
    start_date = "2025-01-01T00:00:00Z"
  }
}

sink {
  Console {}
}
```
