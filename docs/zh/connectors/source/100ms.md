# 100ms

`OneHundredMs` Source 以有界方式读取 100ms 服务端 API，并行度为 1。端到端测试使用 SeaTunnel Zeta。

使用 `token`，或同时配置 `access_key` 与 `secret_key`。使用密钥对时，连接器签发有效期 24 小时的 Management JWT，并在过期前更新。收到 HTTP 401 后，可在尝试次数允许时重新生成一次。直接配置的 Token 原样发送。请通过部署环境的密钥机制提供认证值。[100ms 认证文档](https://www.100ms.live/docs/get-started/v2/get-started/security-and-tokens)

## Source 参数

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `api_url` | String | `https://api.100ms.live` | 受信任的 HTTPS 地址，允许指定端口或末尾的斜杠。 |
| `token` | String |  | 现有的 Management Token，省略 Bearer 前缀。 |
| `access_key` | String |  | 应用的 Access Key。生成 Management Token 时与应用密钥同时配置。 |
| `secret_key` | String |  | 应用密钥，用于 HS256 签名。 |
| `resources` | List&lt;String&gt; | 全部八个 | 按读取顺序列出资源，名称不能重复。 |
| `start_date` | String |  | 房间、模板和录制记录的更新时间下界，包含该值。使用以 Z 结尾的 ISO-8601 UTC 时间。 |
| `page_size` | Integer | `100` | 列表每页大小，范围 10–100。 |
| `max_pages` | Integer | `10000` | 单次列表扫描或子资源快照中的最大页数，范围 1–20,000。 |
| `max_parents` | Integer | `10000` | 每个子资源最多遍历的唯一父资源数，范围 1–20,000。 |
| `max_response_bytes` | Integer | `4194304` | 分别限制网络响应和解压后内容的字节数，范围 1,024–16,777,216。 |
| `max_records_per_response` | Integer | `5000` | 每个响应最多返回的记录数，包括 peer 映射中的成员。范围 1–20,000。 |
| `connect_timeout_ms` | Integer | `10000` | 建立 TCP 连接的超时毫秒数，范围 1–300,000。 |
| `read_timeout_ms` | Integer | `10000` | TLS 握手及响应读取的空闲超时时长，范围 1–300,000 毫秒。 |
| `request_timeout_ms` | Integer | `30000` | 单次分页请求的总时限，涵盖 I/O、解析、重试和等待。范围 1–300,000 毫秒。 |
| `max_attempts` | Integer | `3` | 每个请求最多尝试次数，包含首次请求。范围 1–10。 |

## 资源

| 资源 | 输出记录 |
| --- | --- |
| [`sessions`](https://www.100ms.live/docs/server-side/v2/api-reference/Sessions/list-sessions) | 活跃及非活跃会话。 |
| [`rooms`](https://www.100ms.live/docs/server-side/v2/api-reference/Rooms/list-rooms) | 启用与停用的房间。增量字段为 `updated_at`。 |
| [`active_room_peers`](https://www.100ms.live/docs/server-side/v2/api-reference/active-rooms/list-peers) | 每个房间的 peer 映射成员对应一行。没有活跃会话的房间没有 peer 记录。 |
| [`templates`](https://www.100ms.live/docs/server-side/v2/api-reference/policy/list-templates) | 模板对象。增量字段为 `updatedAt`。 |
| [`template_settings`](https://www.100ms.live/docs/server-side/v2/api-reference/policy/retrieve-settings) | 每个模板的一份完整设置对象。 |
| [`templates_destinations`](https://www.100ms.live/docs/server-side/v2/api-reference/policy/retrieve-destinations) | 每个模板的一份完整目的地配置对象。 |
| [`analytics_events`](https://www.100ms.live/docs/server-side/v2/api-reference/analytics/overview) | 按房间读取事件。每个房间的服务端快照在 24 小时后过期，事件最长保留 30 天。 |
| [`recordings`](https://www.100ms.live/docs/server-side/v2/api-reference/recordings/list-all-recordings) | 录制作业元数据。增量字段为 `updated_at`。 |

输出列为 `resource`、`record_id`、可空的 `parent_id`、可空的 `updated_at` 和 `data`，类型均为 STRING。`data` 保留完整 JSON 对象，包括嵌套值、null 和高精度的整数与小数。数据中可能包含服务端返回的用户元数据或存储配置。

Peer 的 `record_id` 来自映射键。设置和目的地配置使用父模板 ID。事件有服务端 ID 时使用该 ID，否则使用 JSON 对象的 SHA-256 标识。

## 抽取与恢复

未配置 `start_date` 时，所有选定资源都全量读取。配置后，房间、模板和录制记录使用从 `start_date` 到首次作业启动时刻的本地更新时间窗口，包含边界。更新时间缺失或未设置时使用创建时间。两者都缺失时增量抽取失败。其他资源仍全量读取。发现子资源时，遍历所有相应父房间或模板，更新时间窗口只影响父资源本身的输出。

分页由响应游标决定。只要有有效的下一页游标，短页和空页也会继续。重复游标、相邻页重复返回同一组记录、意外响应格式或超过配置上限都会使抽取失败。分析事件的游标过期或被服务端拒绝时，作业失败并保留该错误，避免自动从头建立新快照。

读取器在每行被接收后让出执行，避免在整个已解码页面输出期间一直持有检查点锁。v2 检查点保留当前页游标、已接收行数、五个输出列的固定长度滚动摘要、子资源遍历位置及原始窗口上限。恢复时重新请求同一页，先校验完整的已接收前缀，再精确跳过这些行；前缀变更、重排或缺失会在输出新行之前失败。仅在最后一条符合条件的行被接收后才推进下一页游标或扫描阶段。响应载荷和凭据不进入检查点。这是尚未发布的新连接器，目标格式为 v2，不支持合并前临时实现生成的检查点。恢复时保持 API 地址、账号、资源列表、每页大小及起始时间一致。分析事件即使只接收了第一页的部分行，也保留首次请求的原始时间；续页或部分页恢复超过 24 小时窗口时失败。重新请求没有游标的第一页不能建立不可变的服务端快照：前缀校验能发现已接收行的变更，尚未接收的后缀仍可能变化。服务端列表可能在抽取期间发生变化，各资源之间没有统一的服务端快照。会话或房间跨状态切换，或重放检查点后的行时，可能产生重复数据。

HTTPS 使用 Worker JVM 的证书信任库并验证主机名。连接器支持 gzip，限制请求时长，不跨响应保留 JSON 字段名符号，并在错误诊断中隐藏响应体。HTTP 429 和可重试的 5xx 使用有限退避，遵循有效的 `Retry-After`。出现重定向时请求失败。

## 示例

```hocon
env {
  job.mode = "BATCH"
  parallelism = 1
}

source {
  OneHundredMs {
    access_key = ${HMS_ACCESS_KEY}
    secret_key = ${HMS_SECRET_KEY}
    resources = ["rooms", "active_room_peers", "recordings"]
    start_date = "2025-01-01T00:00:00Z"
  }
}

sink {
  Console {}
}
```
