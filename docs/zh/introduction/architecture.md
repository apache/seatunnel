# SeaTunnel 工作原理

## 新用户先需要知道什么

第一次接触 SeaTunnel 时，您并不需要先理解所有内部模块。
更实用的顺序通常是：

1. 先在本地跑通一个任务，
2. 再理解配置文件结构，
3. 再去挑选连接器，
4. 最后在需要时回来看运行原理。

SeaTunnel 最容易理解的方式是：**它是一条由配置文件驱动、由执行引擎运行起来的数据管道。**

## 四个最核心的组成部分

```
┌─────────────────────────────────────────────────────────────┐
│                        作业配置                              │
│                   (HOCON / SQL / Web UI)                     │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     SeaTunnel 核心层                         │
│               (作业解析器、协调器、调度器)                     │
└─────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│    Source     │────▶│   Transform   │────▶│     Sink      │
│   数据源连接器  │     │   (可选)      │     │   目标连接器   │
└───────────────┘     └───────────────┘     └───────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                        执行引擎                              │
│         SeaTunnel Engine (Zeta) / Flink / Spark              │
└─────────────────────────────────────────────────────────────┘
```

### 1. 配置文件定义作业

配置文件决定了 SeaTunnel 要读取什么数据、如何转换、写到哪里，以及运行时使用哪些引擎参数。

### 2. Source、Transform、Sink 定义数据路径

SeaTunnel 作业始终围绕一条稳定的数据路径展开：

* **Source**：从外部系统读取数据。
* **Transform**：按需对数据做过滤、映射、字段处理等转换。
* **Sink**：把结果写入目标系统。

### 3. 引擎决定作业跑在哪儿

SeaTunnel 可以把同一套基于连接器的作业模型运行在多个引擎上。
对于大多数新用户，推荐优先从 [SeaTunnel Engine (Zeta)](../engines/zeta/about.md) 开始；只有在现有环境已经深度依赖 Flink 或 Spark 时，再切到对应平台。

### 4. 检查点和状态保证正确性

对于长时间运行或需要容错的任务，引擎会负责协调运行时状态、检查点和恢复行为。
刚开始使用时您不需要先掌握这些内部细节，但正是这些机制让 SeaTunnel 能支撑生产级同步任务。

## 连接器模型

| 组件 | 说明 |
|------|------|
| **Source** | 从外部系统读取数据（数据库、文件、消息队列） |
| **Transform** | 数据转换（字段映射、过滤、类型转换） |
| **Sink** | 将数据写入目标系统 |

连接器 API 与具体执行引擎解耦，这也是同一套作业模型能够跨多个引擎复用的原因。

## 执行引擎

| 引擎 | 适用场景 |
|------|---------|
| **SeaTunnel Engine (Zeta)** | 数据同步、CDC、低资源消耗 |
| **Apache Flink** | 复杂流处理、已有 Flink 基础设施 |
| **Apache Spark** | 大规模批处理、已有 Spark 基础设施 |

## 运行流程

```
Source ──▶ [分片] ──▶ Reader ──▶ Transform ──▶ Writer ──▶ Sink
  │                      │                        │
  │                      ▼                        │
  │              Checkpoint/状态                   │
  │                      │                        │
  └──────────────────────┴────────────────────────┘
                    容错机制
```

从高层视角看，SeaTunnel 的运行过程主要是：

1. 解析配置文件，
2. 组装从 Source 到 Sink 的执行链路，
3. 把任务交给所选引擎执行，
4. 在运行过程中跟踪状态、进度和容错信息。

## 当您继续深入时会看到什么

当您从入门页继续深入到系统架构文档时，主要会看到这些更深层的话题：

* 连接器如何被翻译到不同引擎，
* 调度和资源管理如何工作，
* 检查点和精确一次语义如何落地。

## 模块结构

```
seatunnel/
├── seatunnel-api/           # 核心 API 定义
├── seatunnel-connectors-v2/ # Source & Sink 连接器
├── seatunnel-transforms-v2/ # Transform 插件
├── seatunnel-engine/        # SeaTunnel Engine (Zeta)
├── seatunnel-translation/   # 引擎适配器 (Flink/Spark)
├── seatunnel-core/          # 作业提交 & CLI
├── seatunnel-formats/       # 数据格式处理
└── seatunnel-e2e/           # 端到端测试
```
